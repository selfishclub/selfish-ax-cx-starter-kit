# 04 · 슬랙이 아니어도, 카카오 채널이 아니어도 돼요

구조에서 바뀌는 건 **읽기(sources)와 보내기(deliver)** 두 조각뿐이에요. 가리기 · 맥락 읽기 · 판별 · 초안 · 카드 · 브리핑 · 학습은 그대로예요.

## 문의를 받는 곳이 다를 때

| 채널 | 되나 | 메모 |
|---|---|---|
| **이메일** (Gmail · 네이버) | ✅ 더 쉬움 | 공식 API. 안 읽은 메일만 가져오면 됨. 카카오의 「화면 읽기」가 통째로 빠져요 |
| **채널톡** | ✅ 더 쉬움 | 공식 API · 웹훅 |
| **인스타 DM** | ✅ | Meta 공식 API. **비즈니스 계정 심사 · 앱 신청이 먼저**예요 |
| **네이버 톡톡** | ✅ | 공식 API. **파트너 신청이 먼저** |
| **카카오 채널 1:1** | ⚠️ | 수신 API 없음 → 관리자 화면을 브라우저 에이전트로 읽기 (이 키트의 원형) |
| **개인 카톡 · 오픈채팅** | ❌ | 공식 길은 방장봇뿐. 그 이상은 비공식이라 **우리는 안 써요** |

프롬프트 B의 `[상황]` 첫 줄에 채널만 바꿔 넣으면 돼요. 수집기는 `sources/<채널>.js` 한 파일로 두고, 공통 모양(`{ source, key, customerName, receivedAt, body, context, history }`)으로 돌려주게 하면 나머지는 안 건드려요.

## 버튼을 누르는 곳이 다를 때

| 메신저 | 되나 | 메모 |
|---|---|---|
| **슬랙** | ✅ | 우리 선택. 앱 만들고 → 할 일 정해 주고 → 채널에 초대하면 끝. 슬랙 앱은 「슬랙 안에 들어와 일하는 직원 계정」이에요 |
| **디스코드 · 텔레그램** | ✅ | 메시지 아래에 버튼을 달 수 있는 메신저면 뭐든 돼요 |
| **이메일로 받기** | △ | 버튼 대신 「답장으로 OK」 같은 규칙이 필요해요. 여러 명이 같이 보긴 어려워요 |

## 브라우저 에이전트가 다를 때 (카카오 채널처럼 화면을 읽어야 할 때)

| 도구 | 성격 | 언제 |
|---|---|---|
| **Playwright** (우리 선택) | 뒷방에서 창 없이 일하는 직원 | 밤에 수천 건, 사람 없이, 5분마다. 실수해도 다시 돌리면 됨. 무료 · 맥/윈도우 |
| **Aside** | 내 옆에서 화면을 같이 보는 직원 | 로그인된 내 브라우저 그대로. 한 건씩 사람이 보면서. 자영업자 「리뷰 원터치」는 답글 채우기에 이걸 썼어요 |
| **ego lite** | 위와 비슷 | 맥에서 쓰기 편해요 |

읽기(수집)는 창 없이 자주 도는 Playwright, 손님에게 바로 보이는 쓰기(발송 · 답글 채우기)는 사람이 보면서 하는 에이전트 — 이렇게 나눠 써도 돼요.

## 바꿀 때 지킬 것

- 어떤 채널이든 **읽기 전용으로 시작**하고, 발송은 사람이 허락할 때까지 꺼 둬요.
- 로그인은 사람이 창에서. 비밀번호는 어디에도 저장하지 않아요.
- 채널이 바뀌어도 `policy/answers.md`는 같은 걸 써요. 정책은 채널의 것이 아니라 우리 것이에요.
