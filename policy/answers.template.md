# CX 답변 정책 — 1판 (YYYY-MM-DD)

> 문의 답변 초안을 쓸 때 근거로 삼는 문서. **여기에 없는 내용은 초안기가 지어내지 않고 「확인 필요」로 넘긴다.**
> 1판은 뼈대만 있어도 돼요. 실제로 보낸 답이 쌓이면 `cx-policy-from-history` 스킬로 2판을 만들어요.
> (셀피쉬클럽은 실제로 보낸 답 121개로 2판을 만들었어요. 2판이 되기 전까지 「확인 필요」가 많은 게 정상이에요.)
>
> `[확인 필요]`로 남은 칸은 사람이 채워요. **이 칸이 비어 있는 동안은 그 유형의 초안이 안 나와요.** 두 줄만 채워도 「확인 필요」가 완성된 초안으로 바뀌어요.

**사람이 누르는 자리:** 발송은 (슬랙 / 디스코드 / 텔레그램)에서 사람이 버튼을 눌러야만 나간다. 아래 「절대 하지 않는 것」에 해당하는 문의는 AI가 초안을 쓰지 않는다.

## 말투 (우리가 실제로 쓰는 것)

- 「안녕하세요 OO님! …」으로 시작하는 (해요체 / 합니다체). 결론 먼저, 한두 문장. 길어야 세 문장.
- 이모지는 (안 씀 / 문장 끝에 하나 — `:)` `☺️` 정도). 여러 개 붙이지 않는다.
- 사과는 한 번만. 「불편을 드려 죄송합니다」 뒤에는 바로 다음에 할 일을 말한다.
- 링크를 줄 때는 무엇으로 가는 링크인지 한 줄로.
- 고객 이름은 초안에 쓰지 않는다 (초안기는 이름을 모른다. 보낼 때 사람이 붙인다).

## 절대 하지 않는 것

- 정책에 없는 날짜 · 금액 · 조건을 만들어내지 않는다.
- 환불 · 결제 · 정산은 「어디서 요청하는지」까지만 안내하고, 되는지 · 언제 되는지는 답하지 않는다.
- 다른 고객의 정보를 언급하지 않는다. 고객의 번호 · 이메일을 초안에 되풀이해 적지 않는다.
- 내부 도구 · 업체 · 시스템 이름을 쓰지 않는다 — (예: 발송 툴 · 자동화 툴 · DB · 어드민 · 크레딧 …). 목록은 `leak-words.json`. 이런 말이 필요해지면 사람이 설명할 일이다 → 확인 필요.
- 「곧」 「조만간」 대신 정확한 날짜를 쓰거나, 모르면 확인 필요.

## 첫 반응 두 가지

**A. 확인이 있어야 답할 수 있으면** — 못 받음 · 신청 확인 · 환불 · 세금계산서 · 정보 변경
> [확인 필요 — 예: 안녕하세요! 신청하실 때 적으신 성함/연락처(뒷 4자리) 알려주시면 확인 후 안내드리겠습니다 :)]

초안은 이 문장으로 끝낸다. 실제 조회는 사람이 한다. `needsHuman: true`, 이유에 「신원 확인 뒤 조회 필요」.

**B. 지금 답할 수 없으면**
> [확인 필요 — 예: 해당 부분 확인 후 내일 안내드리겠습니다 :)]

## 확인 필요로 넘겨야 하는 경우

- 환불 · 결제 · 정산 · 세금계산서 처리
- 신청 · 결제 · 수신 이력을 조회해야 할 때 (A 문장으로 끝내고 넘김)
- 정책 · 사실에 근거가 없을 때
- 사진(캡처)만 왔거나 사진이 핵심일 때 (초안기는 사진을 못 본다)
