# cx-weekly-learn — 일주일에 한 번, 규칙에 더할 것 · 고칠 것

## 배움 = 모델 훈련이 아니라 정책 문서 고치기

AI를 따로 훈련시키는 게 아니에요. 초안기가 읽는 **정책 문서를 새 데이터로 고치는 것**이 배움이에요. 셀피쉬클럽은 일요일 22시에 자동으로 돌아요. 실제 예: 방 10개 · 고객 말 127 · 보낸 답 83을 읽고 「할부 변경 문의에 우리는 재결제 후 취소로 안내하고 있는데 규칙엔 확인 필요로만 적혀 있다」를 찾아 규칙 수정안을 올렸어요.

## 순서

1. **재료 모으기 (가린 사본만).** 지난 7일 대화가 있던 방의 메시지(이름 · 번호 · 이메일 가린 뒤) + 그 주 카드에서 사람이 내린 결정(이대로 보냄 · 고쳐서 보냄(고친 문장) · 건너뜀 · 확인 필요로 넘김). 사용자가 붙여 넣거나, v2라면 `cx-data/`에서.
2. **나란히 놓고 비교.** 우리가 실제로 보낸 답 vs `policy/answers.md`. 찾는 것 —
   - 규칙에 **없는** 유형인데 답을 보낸 것 → 「더할 것」
   - 규칙과 **다르게** 답한 것 → 「고칠 것」(규칙이 낡았거나, 답이 예외였거나 — 어느 쪽인지 근거 대화와 함께)
   - 「확인 필요」로 넘겼는데 사람이 매번 같은 답을 쓴 것 → 표준 답으로 올릴 후보
   - 고쳐서 보낸 문장이 반복되는 것 → 말투 · 표준 답 갱신 후보
3. **수정안 쓰기.** 항목마다: 지금 문장 · 바꿀 문장(바로 쓸 초안 문장) · 근거 대화(가린 채, 날짜) · 왜. 한 번에 **1~3개**만. 많이 찾았으면 「이번 주 1건 · 다음 주 후보 N건」으로 나눈다.
4. **PR로 올린다.** `main`에 직접 쓰지 않는다. 브랜치 `cx/learn-YYYY-MM-DD` → `policy/answers.md`만 고친 커밋 → PR(제목 「주간 학습 YYYY-MM-DD — 더할 것 N · 고칠 것 M」, 본문에 3번 표). 꼬리표 `cx`.
5. **알린다.** 사용자(또는 슬랙 브리핑)에 「승인 대기 — 수정안 N건, PR 링크」 한 줄. **Merge는 사람이.** Close 하면 없던 일.
6. **다음 주 확인.** 반영된 뒤 같은 유형의 「확인 필요」가 줄었는지 본다.

## 지키는 것

- 가리지 않은 원문을 읽지 않는다. 수정안 · PR 본문에도 이름 · 번호 없음.
- 환불 · 결제 · 개인정보 유형은 「표준 답」 후보로 올리더라도 처리 여부 문장은 넣지 않는다. 「어디서 요청하는지」까지만.
- 근거 대화가 1건뿐이면 「후보」로만. 2건 이상이면 수정안.
- 정책 문서를 직접 덮어쓰지 않는다. 브랜치 + PR.

## 자동으로 돌리려면

Claude Code 루틴(예약 작업)에 「일요일 22시 · `cx-weekly-learn` 스킬로 지난 7일 학습 · PR까지」로 걸어 두면 돼요. 보안 점검도 같은 방식으로 매주 돌릴 수 있어요.
